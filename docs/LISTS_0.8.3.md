# Lists — Folio 0.8.3

Want to Read is a pinned automatic list within Lists, alongside Currently Reading and Finished. It includes active catalogue and EPUB entries whose displayed reading state matches; owning a file does not disqualify a book. Existing linked catalogue entries count once. Hardcover observations and reader activity use the same precedence as library badges; local status updates remain separate from publishing.

The pinned list is a derived view, not a new Room shelf or copied membership dataset. Existing records/UUIDs/list memberships remain unchanged. Its name and definition are fixed. To add/remove a book, use Book actions → Change phone reading status (or the batch status action in Library). Actual observed reader activity takes precedence as before. Catalogue entries with no explicit status or cloud observation default to Want to Read. When an unread EPUB is attached, catalogue reading intent now remains visible until the EPUB has its own reading state. This fallback affects presentation rather than overwriting database records or KOReader activity.

The Lists overview has pinned reading rows and compact user-list cards in one scrollable surface. Transfer configuration lives in Transfer options with an explicit preview and opt-in sync switch; the overview shows an included-in-sync indicator. Existing create/edit/delete and smart rules are retained. Pinned and user lists open inside the Lists tab with the familiar anchored search, Refine, view toggle and cover badges. All lists/System Back returns to overview; book details return to the same list. Each list has separate saveable search/view/refinement state. Batch selection deliberately opens Library, where its existing action toolbar lives.

Discovery no longer contains a separate Want to Read tab or legacy duplicate wish-book browser. Saving a discovery result opens Lists → Want to Read after persistence succeeds. EPUB attachment, external search, Hardcover matching/current progress, local removal and explicit Want-to-Read publication use the unified book details/actions flows. Adding to Hardcover remains an explicit action on an eligible matched catalogue book, not an automatic consequence of local saving.

No schema or dependency migration. Real phone/emulator navigation, TalkBack, large font and layout acceptance still required; test/build results are recorded separately in VALIDATION.md.
