## KOReader integration findings

* **SSH/SFTP:** KOReader's [SSH documentation](https://github.com/koreader/koreader/wiki/SSH) describes Dropbear plus an OpenSSH SFTP subsystem, a configurable port (often 2222), and authorized public keys. Some jailbreaks expose another SSH service. Users must provide their actual host, port, user, folder and fingerprint; Folio does not enable insecure passwordless login.
* **Calibre wireless:** the inspected `wireless.lua` implements the smart-device protocol. `GET_BOOK_FILE_SEGMENT` reads safe relative paths under the configured inbox, including sidecars if accessible there. It does not grant arbitrary filesystem access. Current master also has collection get/update operations with version checks. This is promising for cooperative collection writes, but support must be negotiated against the installed KOReader version.
* **OPDS:** useful pull-based catalogue/download workflow. It requires an HTTP catalogue server on the phone and reader interaction. It does not by itself deliver reverse annotation sync or authoritative device inventory. Deferred.
* **Sidecars:** `getSidecarDir()` strips the last filename extension and supports adjacent `.sdr`, a central metadata directory, or hashed locations. The filename is `metadata.<extension>.lua`; legacy candidates are also searched. Reading locations use document pointers such as `last_xpointer`, not merely a percentage. Lua data must be parsed as bounded data, never evaluated.
* **Collections:** `readcollection.lua` uses `collection.lua` in the settings directory. Membership is tied to document paths and updated in-memory state. Do not rewrite that file while KOReader runs. Use a supported wireless operation or a device-side plugin that calls collection APIs.
* **Statistics:** `statistics.sqlite3` contains `book`, `page_stat_data`, a derived `page_stat` view, and supporting tables. `page_stat` rescales page data to the current layout. WAL mode is used when supported: downloading only the main file while open can miss data. Require a cooperative SQLite snapshot or reader-close procedure, never casually copy a live database.
* **Progress ecosystem:** the [official sync server](https://github.com/koreader/koreader-sync-server) is AGPL-3.0 and synchronises reading position through account-authenticated HTTP APIs. KOReader's kosync plugin derives document identity using a configured binary checksum or filename scheme. This is neither ebook transfer nor general annotation sync. It should remain an optional future integration; this app requires no account/server.

## Transport decision

Start with SFTP because it supports authenticated push, inventory and readback without implementing a Calibre server. Pin SHA256 host keys before authentication. Prefer ECDSA private keys compatible with the documented KOReader setup; retain password mode for installations with a real password. Do not weaken modern SSH algorithms automatically for older servers.

SFTP does not solve reading-state merges. Initial uploads are new-file only. Changed previously transferred revisions are conflicts even when their old path is absent. A new safe replacement workflow will require sidecar/identity snapshots and a KOReader compatibility fixture matrix.

## 0.2 implementation follow-through

The Reliure comparison led to independently implemented portable backups, smart shelves and scoped transfers, read-only KOReader sidecar retrieval, Markdown exports, series navigation and user-reviewed Open Library enrichment. Provider protocol references are the [Open Library Search API](https://openlibrary.org/dev/docs/api/search) and [Covers API](https://openlibrary.org/dev/docs/api/covers). Live search returned a work plus an edition key; the actual compiled Kotlin client successfully resolved editions and downloaded a redirected JPEG on the JVM; mock API fixtures exercise work/edition differences, incomplete data and bounded covers. Only Open Library is implemented; Google Books, BnF and public-domain discovery remain future integrations.

The optional Folio bridge uses the inspected KOReader ReadCollection API (`addCollection`, `addItemsMultiple`, `write`) and lua-ljsqlite3 interfaces (`open`, `exec`, `rowexec`, `close`). Original plugin code is separately licensed AGPL-3.0-or-later, not copied from Reliure or KOReader. It provides confirmed additive collection requests and a transaction-consistent statistics export. Runtime interoperability is not established by source inspection or host fixture tests; see VALIDATION.md and PLUGIN.md.


### 0.3.0 discovery follow-through

Inspected Hardcover’s official published GraphQL schema and the MIT KOReader Hardcover integration’s API patterns. Independently implemented 5 schema-validated operations: current account, ranked book search, book hydration, current user's existing library entry, and Want to Read insertion. Remote search/mutations are fixture-tested, not authenticated-account validated. Google’s current Android OCR guide specifies bundled Latin `com.google.mlkit:text-recognition:16.0.1` (minimum API23, compatible with app min26), used for on-device editable text hints. Book/work matches require confirmation and do not assert edition identity. Full formats, licensing and provenance are in `DISCOVERY.md`; no upstream plugin code or copyrighted artwork was copied.


### KOReader temporary access (0.3.1)

Current KOReader SSH plugin uses Dropbear `-n` for its **Login without password** toggle and `-s` for key-only authentication. The patched mode accepts an arbitrary password. Folio independently implements a deliberate password-authentication dummy for that mode; no Dropbear/KOReader source is linked or copied. The upstream UI controls were inspected at <https://github.com/koreader/koreader/blob/master/plugins/SSH.koplugin/main.lua> and the patch at <https://github.com/koreader/koreader-base/blob/master/thirdparty/dropbear/nopasswd-hack.patch>. The host-key probe does not authenticate or disable later pin checks. User-confirmed trust on first use removes the computer/terminal prerequisite while preserving explicit trust of the device key.
